# News Analyzer – прототип для анализа новостного фона (отдел форензик)

## Архитектура и стек технологий

### Обязательные требования (из ТЗ)
- **Python 3.11+**
- **FastAPI** – веб-фреймворк
- **Docker** – контейнеризация

### Выбранный стек с обоснованием

| Компонент | Технология | Обоснование |
|-----------|------------|--------------|
| API | FastAPI | Асинхронный, автодокументация, встроенная валидация Pydantic |
| Фоновая обработка | Celery + Redis | Не блокировать API при анализе новостей; Redis – брокер и кэш |
| База данных | PostgreSQL | ACID, индексы, полнотекстовый поиск, диагностика транзакций |
| Кластеризация | scikit-learn (TF-IDF + DBSCAN) | Не требует числа кластеров, устойчив к шуму |
| Извлечение сущностей | Natasha (NER для русского) | Компании, локации, отрасль (по ключевым словам) |
| Тональность (ранжирование) | RuBERT (опционально) + rule‑based fallback | SOTA для русского, но без модели работает словарный метод |
| Контейнеризация | Docker + Docker Compose | Локальное развёртывание, воспроизводимость |

## Расчёт мощностей

### На 100 новостей в сутки
- **FastAPI + Uvicorn**: 0.5 vCPU, 512 MB RAM
- **Celery worker**: 1 vCPU, 2 GB RAM (загрузка модели RuBERT)
- **PostgreSQL**: 1 vCPU, 1 GB RAM, 10 GB SSD
- **Redis**: 256 MB RAM
- **Сетевое хранилище (логи, сырые новости)**: 10 GB

**Обработка одной новости** ≈ 1-2 сек (парсинг, NER, TF-IDF, кластеризация, трансформер).  
100 новостей ≈ 3 минуты работы Celery в день. Нагрузка минимальная.

### Масштабирование до 10 000+ новостей/сутки

| Компонент | Горизонтальное масштабирование |
|-----------|--------------------------------|
| FastAPI | За балансировщиком, несколько реплик (K8s) |
| Celery | Autoscaling workers (KEDA), увеличение количества |
| PostgreSQL | Репликация (read replicas), партиционирование по дате |
| Redis | Redis Cluster |
| Кластеризация | Онлайн-вариант (mini-batch k-means или HDBSCAN с обновлением) |
| Тональность | Кэширование эмбеддингов, квантизация модели (ONNX) |

**Пиковая нагрузка**: 10 000 новостей / час = ~3 новости в секунду.  
Один Celery worker с GPU (или 4 CPU-воркера) справится при batch-обработке.

## План MVP (минимально жизнеспособный продукт)

1. **Настройка окружения** – `docker-compose.yml` с PostgreSQL, Redis, minio (для хранения).
2. **Модуль сбора новостей** – парсер RSS лент или заглушка с тестовыми данными.
3. **API приёма новостей** – `POST /news` → ставит задачу в Celery.
4. **Фоновый процесс** – Celery worker выполняет:
   - Извлечение сущностей (компания, локация, отрасль)
   - Кластеризацию (DBSCAN на TF-IDF)
   - Тональность (RuBERT или fallback)
5. **Сохранение результатов** – в PostgreSQL (таблицы `news`, `clusters`, `sentiments`).
6. **API получения аналитики** – `GET /analysis/{company}` → кластеры, динамика тональности.
7. **Дашборд (опционально)** – Streamlit или FastAPI + Chart.js.

## Масштабирование до production-ready

- **Очередь**: Celery + Redis с retry, dead-letter, мониторингом (Flower).
- **Инкрементальная кластеризация**: замена DBSCAN на HDBSCAN с частичным переобучением.
- **Кэширование**: Redisearch для эмбеддингов, результатов тональности (TTL).
- **Мониторинг**: Prometheus + Grafana (latency, errors, queue length).
- **CI/CD**: GitHub Actions (тесты, сборка образа, деплой на k8s).
- **Безопасность**: JWT, HTTPS, санитизация входных данных.
- **Резервное копирование**: pg_dump + WAL архивация.

## Запуск прототипа

### Локальный запуск (без Docker)

1. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
   *Примечание:* для работы полноценного ранжирования нужны `torch` и `transformers` – установка займёт ~1 ГБ. Без них работает rule‑based fallback.

2. Проверьте кластеризацию:
   ```bash
   python clustering.py
   ```

3. Проверьте тональность (rule‑based):
   ```bash
   python ranking.py
   ```

4. Пример работы кластеризации на новостях с повторяющимися компаниями:
   ```bash
   python -c "
   import json
   from clustering import NewsClusterer
   with open('sample_news_clusters.json') as f:
       news = json.load(f)
   clusterer = NewsClusterer(eps=0.8, min_samples=2)
   labels = clusterer.cluster(news)
   print('Cluster labels:', labels)
   "
   ```

### Запуск с Docker (полный стек)

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/kalikrit/news-analyzer.git
   cd news-analyzer
   ```

2. Запустите все сервисы:
   ```bash
   docker-compose up --build
   ```

3. API будет доступно по адресу: [http://localhost:8000](http://localhost:8000)

4. Откройте документацию Swagger: [http://localhost:8000/docs](http://localhost:8000/docs)

## Результаты тестирования

### Кластеризация
На наборе из 8 новостей (Газпром – 2 шт., Сбербанк – 2 шт., Роснефть – 2 шт., Путин – 1, ЦБ – 1) алгоритм правильно выделил три кластера по компаниям и два шумовых элемента (-1):

```
Кластер 0: Газпром запустил месторождение, Газпром увеличил дивиденды
Кластер 1: Сбербанк запустил ипотеку, Сбербанк представил AI-помощника
Кластер 2: Роснефть нашла месторождение, Роснефть заключила контракт
Кластер -1: Путин обсудил экономику, ЦБ РФ сохранил ставку
```

### Ранжирование (тональность)
Без установки `torch/transformers` модуль переключается на rule‑based fallback. Он определяет эмоциональную окраску по ключевым словам (например, «прибыль», «успех» → позитив; «убыток», «падение» → негатив). Для тестовых новостей нейтральных тем результат ожидаемо `neutral`.

Для production рекомендуется установить модель RuBERT (см. `ranking.py`).

## Примечания

- Кластеризация чувствительна к параметру `eps`. В текущих примерах используется `eps=0.8, min_samples=2`.
- Для новых данных параметры можно подобрать экспериментально (чем выше `eps`, тем больше новостей попадает в один кластер).
- Модель RuBERT загружается при первом вызове `SentimentRanker` (1–2 мин, если установлены зависимости).
- Промпт `prompt_db_fixer.md` предназначен для LLM-агента, автоматически исправляющего ошибки транзакций PostgreSQL.
